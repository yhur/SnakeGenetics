Three ideas explain most of this layout:

  • GeneticAI/ knows nothing about windows. The dashboard imports it, never the other way round. That is why the same learning code runs with a window (Dashboard/) and without one (headless.py).
  • genetic.py and snake_ai.py never import each other. The GA only handles lists of numbers (genomes) and their fitness. The game only takes a genome and returns a fitness. A runner (headless.py or main_window.py) carries the numbers between them. See the picture below.
  • SnakeGame/ is used as is. It is a separate repository, added as a submodule. snake_ai.py wraps it instead of changing it.

3Follow a run through the files

The same story, told as the path the program takes through the tree. Steps 1–2 are shared; then the two modes split.

Start-up (both modes)

  1. main.py main() → Config.load_last() in config.py reads settings.json, or uses the defaults.
  2. GeneticAlgorithm(settings) in genetic.py creates 500 random genomes with random_genome() from network.py. (With --load, checkpoint.load() does this instead.)

python main.py --headless

  1. headless.train() starts a pool of worker processes.
  2. It sends every genome to play_game() in snake_ai.py, one game per snake, in parallel.
  3. play_game builds a SnakeAI: a NeuralNetwork (network.py), a Board and a Snake (SnakeGame), and calls step() until the game ends.
  4. Each SnakeAI.step() calls the game's Snake.moveTo() (snake.py), then think() → look() → NeuralNetwork.forward() to choose the next move.
  5. When the game is over, SnakeAI.fitness() → fitness_function().
  6. Back in train() the results are stored on each Individual, then GeneticAlgorithm.next_generation() breeds the next population.
  7. Every 10 generations, and on Ctrl+C: checkpoint.save() writes saves/…npz.

python main.py (dashboard)

  1. Dashboard(ga) in main_window.py builds the window (build_window()) and starts a timer that fires every 16 ms.
  2. start_snake() builds a SnakeAI for snake number index and hands it to BoardView.show_game() and NetworkView.show_brain().
  3. on_timer() → one_move() → game.step(): the same snake_ai.py code as headless step 6, one move at a time.
  4. When the game ends, snake_finished() stores the fitness and moves to the next snake. After the last one it calls ga.next_generation() and chart.set_history().
  5. refresh() updates the labels and asks the views to repaint; their paintEvent()s read the game and the brain.
  6. Apply in the settings form: ConfigPanel emits its applied signal with a new Config → Dashboard.restart() → settings.json. Save / Load…: Dashboard.save() / load_dialog() → checkpoint.save / load.

main.py

Uses: config, genetic, checkpoint, headless / Dashboard · Used by: you

The only file you run. It reads the command line, gets the settings, makes (or loads) the GeneticAlgorithm object ga, and hands it to one of the two runners. ga is the one object everything else works on: it holds the settings (ga.cfg), the population, the generation number and the history.

settings = Config.load(args.config) if args.config else Config.load_last()
if args.load:
    ga = checkpoint.load(args.load, settings)     # snakes + brain from the file, the rest from settings
else:
    ga = GeneticAlgorithm(settings)

if args.headless:
    from GeneticAI import headless
    headless.train(ga, args.generations, args.workers, args.save)
else:
    from PyQt5.QtWidgets import QApplication
    from Dashboard.main_window import Dashboard

GeneticAI/: the learning

Six files, in the order they build on each other: config and network depend on nothing; snake_ai and genetic each use network; checkpoint and headless sit on top.

genetic.py

Uses: network (random_genome, genome_size) · Used by: main, checkpoint, main_window

The population and the generation step. It never plays a game: it expects every Individual to already have a fitness when next_generation() is called. The top of the file is plain functions on genomes (crossover, mutation); the bottom is the GeneticAlgorithm class that uses them.

NameWhat it does
Individualone snake: genome, fitness, score, steps, age, born_by
sbx_crossovereach child gene is a random blend near the parents' genes
single_point_, two_point_, uniform_crossovercut-and-swap crossovers
gaussian_mutation, uniform_mutationnudge, or replace, about 5% of the genes
GeneticAlgorithm.__init__500 random individuals, empty history
mutation_ratefixed, or shrinking with the generation ("decaying")
record_resultsstep 2: history for the chart, best_ever
select_survivorsstep 3: the 100 fittest (respecting lifespan)
pick_parentstep 4: tournament (default) or roulette wheel
crossoverstep 5: clone, SBX, or the chosen point crossover
mutatestep 6: gaussian or uniform
next_generationruns steps 2–6 and builds the next population. Read this first.
GeneticAI/genetic.py · GeneticAlgorithm.next_generation() 
def next_generation(self):
    """Call this after every snake of the population has played and has a fitness."""
    self.record_results()
    survivors = self.select_survivors()

    children = []
    while len(children) < self.cfg.num_offspring:
        mom = self.pick_parent(survivors)
        dad = self.pick_parent(survivors)
        genome1, genome2, method = self.crossover(mom, dad)
        for genome in (genome1, genome2):
            self.mutate(genome)
            children.append(Individual(genome, born_by=method))

With "plus" selection (default) the next population is survivors + children (100 + 400); with "comma" it is only the children.

headless.py

Uses: checkpoint, snake_ai · Used by: main (with --headless)

Runner 1, and the only parallel code in the project. It is also the shortest complete training loop, so it is the best place to see the whole program in one screen.

GeneticAI/headless.py · train() 
while generations == 0 or done < generations:
    ...
    # Play every snake's game, in parallel. results[i] belongs to population[i].
    jobs = [(ga.cfg, ind.genome) for ind in ga.population]
    results = pool.starmap(play_game, jobs)
    for ind, (fitness, score, steps) in zip(ga.population, results):
        ind.fitness, ind.score, ind.steps = fitness, score, steps

    ga.next_generation()          # same genetic algorithm as the dashboard

Only the settings and a genome go to each worker, and only three numbers come back. Workers ignore Ctrl+C (ignore_ctrl_c); the main process catches it, saves, and stops.

board_view.py

Uses: boards.GameBoard · Used by: main_window

BoardView subclasses the original GameBoard. show_game() points it at the current game's snake and apple; paintEvent() lets the original code draw the board, then draws the vision rays from game.ray_hits, or, with simple inputs, the three cells around the head.

NetworkView draws a brain. show_brain() receives the NeuralNetwork; neuron_positions() lays out one column per layer; paintEvent() draws wires from brain.weights (blue positive, red negative) and neurons from brain.activations.

6Things worth knowing

  • Headless still needs PyQt5 installed. GeneticAI/ never draws, but snake_ai.py imports SnakeGame/boards.py, which imports PyQt5 at the top. No window is opened, so no screen is needed.
  • A genome only fits one brain shape. network.py cuts it by layer_sizes, so changing layers, activations or inputs means a new random population (main_window.restart), and checkpoints keep their own brain settings.
  • One game per snake is a noisy test. Every game starts in a random direction with random apples, so the same genome can score 1 or 300. "Best ever" is the luckiest game; the average score shows real progress.
  • Vision snakes often cannot see the apple. It only shows up when it is exactly on one of the 8 rays. Combined with a deterministic brain, that is why many long games end in a loop (is_looping).
  • Late in training, fitness is just "apples". Beyond about 40 apples, 2 ** apples dwarfs the other terms of fitness_function. Tournament selection only compares order, so it is unaffected; roulette is.
  • Two headless runs share one file unless you pass a different --save, because both write saves/checkpoint_<inputs>.npz.

7Suggested reading order

  1. SnakeGame/snake.py: Direction and moveTo(). Everything builds on these.
  2. GeneticAI/network.py: short. Genome → weights → forward().
  3. GeneticAI/snake_ai.py: top to bottom; it is in the order things happen.
  4. GeneticAI/genetic.py: next_generation() first, then the methods it calls, in order.
  5. GeneticAI/headless.py: now the whole loop fits on one screen.
  6. GeneticAI/config.py, checkpoint.py, main.py: settings, files, start-up.
  7. Dashboard/main_window.py: the same loop, driven by a timer. The view files only if you are curious about the drawing.
