The idea

Every snake has a brain: a small neural network. All its weights and biases are kept in one long list of numbers, its genome (951 numbers with the default brain). The genetic algorithm never trains a brain directly. It breeds better brains, the way animal breeders breed better animals:

500 snakes each play one game          → each gets a fitness score
   → keep the best 100                  (survivors)
   → 200 times: pick 2 parents          (tournament or roulette)
        → crossover → 2 children        (SBX or point crossover)
        → mutate both children          (change a few numbers)
   → next generation = 100 survivors + 400 children
   → repeat

On the dashboard, the snakes play one at a time: snake 1, then 2, up to 500. Then the next generation is bred, and it starts again at snake 1.

2 · Run state

Top right. RUNNING — Space: pause, Q: quit in green, or PAUSED — Space: one move, R: resume in orange. It reminds you which keys do what right now.

3 · Network: the brain

The brain of the snake on the board, drawn as columns of neurons, from inputs on the left to outputs on the right. With the default settings: 32 → 20 → 12 → 3.

Wires

Every line is one weight connecting two neurons.

  • Blue = positive weight: the signal pushes the next neuron up.
  • Red = negative weight: the signal pushes it down.
  • Thicker and brighter = stronger, compared with the strongest wire in the same layer. Strong wires are drawn last, so they appear on top.

Neurons

  • Inputs: white when 0, green when the snake sees something there. The brighter the green, the larger the value.
  • Hidden neurons: grey when silent, cyan when they fire. The brighter, the stronger.
  • Outputs: the move the snake will make next is solid green.

Input labels (32)

The snake looks in 8 directions from its head: U up, UR up-right, R, DR, D, DL, L, UL. For each direction there are three inputs:

LabelMeaningValue
U-WWall in that direction1 / distance to the wall: closer means bigger
U-AApple on that ray1 if seen, else 0 (or 1/distance with Apple/Self vision = 1 / distance)
U-SIts own body (Self) on that ray1 if seen, else 0 (or 1/distance)
HU HD HL HRHead direction: up, down, left, rightexactly one of the four is 1
TU TD TL TRTail direction: which way the tail movesexactly one of the four is 1

8 directions × 3 + 4 + 4 = 32 inputs. With Snake vision = 4 directions, it is 4 × 3 + 8 = 20.

Simple inputs (14)

With Inputs = Simple, the snake does not look along rays. It gets 14 yes/no facts (1 or 0) instead:

LabelMeaning
Wall F / R / Lthe cell forward, to the right, to the left of the head is outside the board
Moving R / D / L / Uthe direction the snake is moving; exactly one is 1
Body F / R / Lits own body is in the cell forward, to the right, to the left
Apple L / R / U / Dthe apple is left of, right of, above, below the head

It learns much sooner, because the answers are handed to it, but it sees only one cell ahead, so long snakes trap themselves. Comparing the two shows that what the snake can see matters as much as how it learns.

Outputs (3)

Forward, Right, Left, relative to where the snake is heading. These are the game's own move encoding (Snake.action_f / action_r / action_l). The output with the highest value wins.

6 · Chart

Green: best score in each generation. Blue: average score. The best score jumps around because it depends on one lucky or unlucky snake; the average shows real progress. The chart fills in after the first generation finishes.

Runs vary a lot. With the default settings, most runs reach 3–5 apples in 150 generations, some take off to 20–40, and long runs go further. If the average stays flat for hundreds of generations, start a new run or add variety.

7 · Settings

Apply: what happens

  • The settings are saved to settings.json. Both modes start from this file, so --headless uses what you last applied here.
  • Brain settings (hidden layers, neurons, activations, inputs, vision) decide the shape of the brain. If they're unchanged, Apply asks: Keep snakes (same snakes, new rules from now on) or New population. If they changed, the old genomes no longer fit, so only New population is possible.
  • When you load a checkpoint, its brain settings come with it, and all other settings stay as you set them.

Settings that don't apply right now are greyed out: Tournament size with Roulette, Lifespan with Comma, Cross points with Random or Uniform.

Population & Selection

SettingMeaning
Parents (μ)How many snakes survive each generation: the μ with the highest fitness. Only they can become parents.
Offspring (λ)How many children are bred each generation.
Selection typePlus (μ+λ): next generation = survivors and children (100 + 400 = 500). Good snakes can stay for many generations. Comma (μ,λ): next generation = children only (400). Every snake plays once and lives on only through its children.
Parent selectionHow each parent is picked from the survivors (see below).
Tournament sizeHow many survivors compete in each tournament. Bigger means the best win more often: faster progress, less variety.
Lifespan (gens)The most generations a snake may survive (Plus only). It stops one old champion from dominating. infinite = no limit.

Picking parents

First the best μ = 100 survive (a simple sort by fitness). Then parents are picked from those 100, 400 times: 200 pairs, each making 2 children.

Tournament

Draw 5 different survivors at random; the fittest of the 5 is the parent. The best survivor wins every tournament it's drawn into. Weak ones rarely win. Only rank matters.

Roulette wheel

Each survivor gets a slice of a wheel sized by its fitness. Spin, and the pointer picks the parent. A snake with 10× the fitness gets about 10× the chances.

Crossover

Crossover mixes two parents' genomes into two children. For each pair:

Crossover rate: cross them at all?  no → both children are copies ("clone")
SBX share:      which kind?         SBX share → SBX
                                    the rest  → the Point crossover below
SettingMeaning
Crossover rateThe chance that a pair is crossed at all. At 1.00 every pair is crossed.
SBX shareThe share of crossed pairs that use SBX. 0.35 means about 35% SBX and 65% point crossover, decided randomly per pair.
SBX ηHow close SBX children stay to their parents (see SBX).
Point crossoverSingle-point, Two-point or Uniform (see below).
Cross pointRandom: a new cut position for every pair. Fixed: always cut at the fractions below.
Cross point 1 / 2Where to cut, as a fraction of the genome: 0.5 = the middle. Point 2 is used only by two-point.

Point crossovers

Each child gets a full genome: some genes from mom, the rest from dad. Values are copied as they are, never changed.

Single-point (one cut, swap the tails)
mom:     M M M M M M | M M M M
dad:     D D D D D D | D D D D
child 1: M M M M M M | D D D D
child 2: D D D D D D | M M M M

Two-point (two cuts, swap the middle)
child 1: M M M | D D D D | M M M
child 2: D D D | M M M M | D D D

Uniform (a coin flip for every gene)
coin:    H  T  T  H  T  H  H  T
child 1: M  D  D  M  D  M  M  D
child 2: D  M  M  D  M  D  D  M

SBX: Simulated Binary Crossover

SBX works gene by gene, with no cut. For each of the 951 weights and biases, it takes mom's value m and dad's value d at the same position, finds their average, and places the two children on either side of it.

u = random number in [0, 1], one per gene
β = (2u)1/(η+1)  if u ≤ 0.5,    β = (1 / (2(1−u)))1/(η+1)  if u > 0.5
x̄ = (m + d) / 2     child1 = x̄ + β·(m − x̄)     child2 = x̄ − β·(m − x̄)

β = 1 gives exact copies: child 1 = mom, child 2 = dad. β < 1 pulls the children toward the average, and β > 1 pushes them past the parents. The pair always keeps the parents' average.

ηTypical βChildren
100 (default)0.98 – 1.02near-copies of the parents (a sharp peak at β = 1)
200.9 – 1.1close to the parents, a little blended
20.3 – 1.7anywhere from near the average to past the parents (a wide, smooth hill)

Why this design: children of good parents should usually look like their parents. The spread follows how different the parents are: wide early on, small once the population agrees, so it fine-tunes on its own. SBX was designed (Deb & Agrawal, 1995) to behave on decimal numbers like single-point crossover does on bits. Example with m = 0.8 and d = 0.2: the average is 0.5, and with η = 100 the children come out about 0.80 and 0.20.

Mutation

After crossover, each child is mutated once.

SettingMeaning
Mutation rateThe chance that each gene changes. 0.05 means about 48 of the 951 genes.
Rate typeStatic: always the same. Decaying: rate ÷ √(generation + 1), so bigger changes early and fine-tuning later.
Gaussian shareThe chance a child gets Gaussian mutation; otherwise it gets uniform.
Gaussian σThe typical size of a Gaussian nudge: about 68% of nudges are within ±σ, 95% within ±2σ.
Uniform range ±Uniform mutation replaces the gene with any value in this range.

Gaussian: nudge

new = old + a small random number from a bell curve. 0.60 → 0.67. It keeps what was learned and fine-tunes it.

Uniform: replace

new = any random value in ±range. 0.60 → −0.83. Big jumps that can break a stuck population, but usually damage the snake.

Fitness

When a snake's game ends, it gets one number. Survival and parent selection look only at this number.

fitness = useful_steps + (2a + 500·a2.1) − a1.2·(0.25·steps)1.3

a = apples eaten, steps = all moves made, and useful_steps = moves, minus those spent circling before starving.

  • Survival: +1 per useful move, a little reward for not dying.
  • Apple reward: grows fast. Eating is by far the most important thing.
  • Slowness penalty: taking many moves to get the apples costs points.

Starving

The original game's rule: a snake of length L starves after 100·(L+1)+200 moves without an apple. A new snake (length 3) gets 600 moves, plus 100 more for every apple it has eaten.

Endless loops

The brain always makes the same move for the same situation, and nothing random happens until an apple is eaten. So if the snake returns to exactly the same state (the whole body in order, plus direction) since its last apple, it will repeat the same moves forever. It is stopped right away and shown as loop. Its fitness is computed as if it had circled until it starved, so the result is identical; it's just faster.

Modes & files

Dashboard: python main.py

One snake at a time, on screen. Easy to follow and explain.

Headless: python main.py --headless

No window. All 500 games of a generation play in parallel, one process per CPU core. Same genetic algorithm, as fast as possible. Ctrl+C stops it and saves.

python main.py --headless -g 500              # stop after 500 generations
python main.py --headless --workers 8         # use 8 processes
python main.py --load saves/checkpoint_vision.npz    # continue in either mode
python main.py --config my_settings.json      # use another settings file
FileWhat it holds
settings.jsonThe settings last applied in the dashboard. Both modes start from it.
saves/*.npzCheckpoints: settings, generation, all 500 genomes and ages, history, the best snake. Headless saves saves/checkpoint_vision.npz (or _simple) every 10 generations and when it stops.

A good workflow: train with --headless, then open the checkpoint in the dashboard to watch the trained snakes play.
