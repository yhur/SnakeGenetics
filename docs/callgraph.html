SnakeGenetics: call flow

What runs, in what order, from python main.py to the next generation of snakes. The two modes share the same core; they differ only in how the games are played.

1 · Headlesspython main.py --headless

One snake at a time, one move per timer tick, driven by Qt's event loop.

1Headless call flow

train() is the whole training loop: play every game in parallel, copy the results back, breed, save.

  • main()
    • Config.load_last()settings last applied in the dashboard
    • GeneticAlgorithm(settings)500 random snakes, or checkpoint.load() with --load
    • headless.train(ga)
      • multiprocessing.Pool(workers)one process per CPU core
      • loopfor each generation until -g generations or Ctrl+C
        • pool.starmap(play_game, jobs)one job per snake; waits for all, results in order
          • in each workerplay_game(cfg, genome)
            • SnakeAI(cfg, genome)same in both
              • NeuralNetwork()genome → weight matrices
              • Board()Snake()Board.generate_apple()
              • think()→look()→brain.forward()decide the first move
            • loopuntil the game is over
              • SnakeAI.step()same in both
                • Snake.moveTo(move)the output neuron with the highest value wins
                • apple eaten → Board.generate_apple(); wall, body or starved → game over
                • is_looping()same state since the last apple → game over
                • think()→look()→brain.forward()decide the next move
            • SnakeAI.fitness()→fitness_function()same in both
            • return (fitness, score, steps)
        • copy each result onto its Individual
        • ga.next_generation()same in both
          • record_results()statistics, best snake so far
          • select_survivors()keep the fittest
          • loopuntil there are enough children
            • pick_parent() ×2mother and father
            • crossover(mom, dad)two child genomes
            • mutate(genome)for each child
          • survivors + children (or children only) → next population
        • print(...)one line of statistics
        • ifevery save_every (10) generations
          • checkpoint.save(path, ga)
      • finallyalways, also after Ctrl+C
        • pool.terminate()
        • checkpoint.save(path, ga)

Workers only play games. The main process copies their results back and breeds the next generation, so the genetic algorithm itself is never run in parallel.

2Dashboard call flow

A window cannot sit in a while loop, so there is no single call stack: Qt calls back into the Dashboard when the timer fires or a key is pressed. on_timer → one_move → step plays the same game as headless's play_game, one move per call.

  • main()
    • Config.load_last()
    • GeneticAlgorithm(settings)or checkpoint.load() with --load
    • QApplication(sys.argv)
    • Dashboard(ga)
      • build_window()create the views, connect the buttons
      • installEventFilter(self)catch Space / R / Q everywhere
      • timer.timeout.connect(on_timer); timer.start(16)about 60 times a second
      • start_snake()
        • SnakeAI(cfg, genome)same in bothbrain, Board, Snake, first apple, first move
        • board.show_game(game)
        • nn_view.show_brain(brain, …)
    • window.show()
    • app.exec_()Qt's event loop: everything below is called from here
      • eventtimer, every 16 ms → on_timer()
        • on_timer()
          • paused → return
          • loopas many moves as the speed setting asks for (Max: for 12 ms)
            • one_move()
              • game.step()same in bothmove, apple, game over, loop check, next move
              • ifthe game is over → snake_finished()
                • snake_finished()
                  • game.fitness()→fitness_function()same in both
                  • store fitness, score and steps; go to the next snake
                  • ifthat was the last snake of the generation
                    • ga.next_generation()same in bothrecord → survivors → parents, crossover, mutate
                    • chart.set_history(history)
                  • start_snake()the next snake's game
          • refresh()update the statistics, repaint
      • eventkey Space / R / Q → eventFilter()
        • pause_or_step()Space: pause; while paused, one one_move() per press
        • resume()R
        • close()Q
      • eventtoolbar and settings buttons
        • Pause · Resume · Quit → the same pause_or_step() · resume() · close() as the keys
        • save()Save → checkpoint.save()
        • load_dialog()Load… → checkpoint.load(), then use(ga)
        • restart(cfg)Apply in the settings panel
        • toggle_vision(on)vision rays on/off
      • eventwindow closed → closeEvent()
        • timer.stop()

The timer runs inside the same process as the window, not in a separate worker. The dashboard saves only when you press Save.
